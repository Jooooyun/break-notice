G3 기술 책임과 exact documentation lock은 성공한 Re-Audit과 Owner
승인에 따라 `OWNER-APPROVED / PASSED`로 승격되었다. 역사적 Final
Audit은 `REVISION REQUIRED`로 변경 없이 유지하고, Re-Audit의
`READY FOR G3 GATE DECISION` 판정은 G3 passage의 근거로 소비되었다.
Prototype 파괴 profile은 모든 category cap `0`이며 Later-Slice의
bounded destruction hard cap과 authored-state·pooling·atomic-admission
규칙은 Owner-approved로 LOCK되었다. 정확한 권위는
[`docs/04_technical/DESTRUCTION_BUDGET_AND_IMPLEMENTATION_RULES.md`](docs/04_technical/DESTRUCTION_BUDGET_AND_IMPLEMENTATION_RULES.md)와
[`ADR-0016`](docs/09_adrs/ADR-0016-BOUNDED-DESTRUCTION-BUDGET.md)를
따른다. 이는 G4/G5 passage, Structural Feature 편입, 성능 합격값 또는
구현 권한을 뜻하지 않는다.

## 절대 고정 사항

- 게임은 **3D TPS**다.
- documentation lock은 **Unity 6000.3.20f1**, **URP 17.3.0**,
  **Input System 1.20.0**, **Cinemachine 3.1.7**,
  **Unity Test Framework 1.6.0**이고 물리는 **GameObject 기반
  PhysX** 방향이다.
- 원거리 염력이나 마법 Grab은 없다.
- 붉은 넥타이는 복장과 시각적 상징일 뿐 물체 연결 도구가 아니다.
- 물체 연결은 허리 릴에서 나오는 **검정·황색 산업용 화물 스트랩, 금속 카라비너, 교체식 클램프**로 하중 지지 금속 Anchor에 수행한다.
- 일반 전투의 활성 동료는 **1명**, 특수 피니셔에서만 최대 2명이다.
- LGT_01은 Records Archive 지역의 after-hours 조명 변주이며 게임 전체의 Global Lighting 또는 Color Grading 기준이 아니다.
- FIN_01은 PR-F-022 `COULD` 기능의 Visual-only conditional direction이며 Vertical Slice 또는 최종 제품 범위에 자동 편입되지 않는다.
- 코미디는 과장된 얼굴이 아니라 진지한 인물과 황당한 물리 결과의 대비에서 나온다.
- 실제 구현은 승인된 요구사항과 인수 테스트 없이는 시작하지 않는다.

## Git 사용 원칙

- `main`: 승인된 기준선만 유지한다.
- 기능 작업은 `task/<ID>-<short-name>` 브랜치에서 수행한다.
- 커밋은 하나의 목적만 가진다.
- 설계 변경은 코드로 먼저 밀어 넣지 않는다. 반드시 Change Request와 ADR을 먼저 승인한다.
