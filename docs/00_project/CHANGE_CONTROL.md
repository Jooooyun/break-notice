# Change Control

## 목적

폭포수 개발에서 설계 변경이 코드에 선행하여 침투하는 것을 막는다. Locked Decision, 요구사항, Canon 비주얼, 성능 예산을 바꾸는 모든 작업에 적용한다.

## 변경 등급

| 등급 | 예시 | 절차 |
|---|---|---|
| C0 | 오탈자, 의미 변화 없는 편집 | 문서 직접 수정 |
| C1 | 수치 튜닝, 파일명, UI 문구 | 영향 문서와 테스트 갱신 |
| C2 | 시스템 동작·입력·데이터 구조 변경 | Change Request + 영향 분석 + 승인 |
| C3 | 장르, 엔진, 카메라, 핵심 루프, 아트 방향 변경 | ADR 대체 + 요구사항 재승인 + 일정 재산정 |

## Change Request 템플릿

```markdown
# CR-XXXX: 변경 제목

- 요청자:
- 날짜:
- 변경 등급:
- 변경 이유:
- 현재 Canon:
- 제안 변경:
- 플레이 경험 영향:
- 기술 영향:
- 아트·애니메이션 영향:
- 테스트 영향:
- 일정·범위 영향:
- 되돌리기 계획:
- 결정: APPROVED / REJECTED / DEFERRED
```

## 승인 규칙

- C2 이상은 구현 전에 승인한다.
- 승인되지 않은 변경을 “임시 코드”로 넣지 않는다.
- 변경 후 `DECISION_LOG`, 요구사항, RTM, 인수 테스트를 갱신한다.
- 이전 문서는 삭제하지 않고 `docs/archive/`로 이동한다.
