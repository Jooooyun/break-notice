# Non-Functional Requirements

## 성능

| ID | 요구사항 |
|---|---|
| NFR-P-001 | 버티컬 슬라이스는 권장 PC에서 1920×1080, 60 FPS를 목표로 한다. |
| NFR-P-002 | 일반 전투에서 동시에 깨어 있는 Dynamic Rigidbody 목표는 30개 이하이다. |
| NFR-P-003 | 실제 물리 큰 파편은 한 사건당 15개 이하를 목표로 한다. |
| NFR-P-004 | 작은 종이·유리·먼지는 Particle/VFX로 처리한다. |
| NFR-P-005 | 활성 적은 일반 방 3~6명, 버티컬 슬라이스 최대 6명이다. |
| NFR-P-006 | 프레임 스파이크가 발생하는 구조 파괴는 사전 풀링과 단계적 활성화를 사용한다. |

## 가독성·사용성

| ID | 요구사항 |
|---|---|
| NFR-U-001 | 플레이어·동료·적·사용 가능 물체가 1초 내 구분되어야 한다. |
| NFR-U-002 | 패스 경로와 물체 진행 방향이 이펙트 없이도 자세와 운동으로 읽혀야 한다. |
| NFR-U-003 | 카메라는 주인공이 들고 있는 Medium 물체 때문에 목표를 가리지 않아야 한다. |
| NFR-U-004 | 카메라 흔들림, 모션 블러, FOV 펀치는 개별로 조절 가능해야 한다. |
| NFR-U-005 | 색상만으로 Light/Medium/Heavy나 팀을 구분하지 않는다. |

## 유지보수성

| ID | 요구사항 |
|---|---|
| NFR-M-001 | 시스템은 인터페이스와 명시적 이벤트 계약으로 분리한다. |
| NFR-M-002 | 물체 데이터·적 데이터·튜닝 값은 ScriptableObject 기반 정의로 관리한다. |
| NFR-M-003 | 런타임 상태를 ScriptableObject 자산에 저장하지 않는다. |
| NFR-M-004 | 모든 기능은 요구사항 ID와 인수 테스트 ID를 추적할 수 있어야 한다. |
| NFR-M-005 | 신규 패키지는 ADR 또는 Change Request 승인 없이 추가하지 않는다. |

## 안정성

| ID | 요구사항 |
|---|---|
| NFR-R-001 | 투척물은 일반 플레이 속도에서 벽·적을 터널링하지 않아야 한다. |
| NFR-R-002 | 물체가 NaN, 무한 속도, 반복 폭발 상태에 빠질 경우 안전 복구한다. |
| NFR-R-003 | Reset 후 모든 런타임 계보, Momentum, 물체 상태가 기준 상태로 돌아와야 한다. |
| NFR-R-004 | 물리 버그가 발생해도 저장 데이터가 손상되지 않아야 한다. |

## 생산성

| ID | 요구사항 |
|---|---|
| NFR-D-001 | 한 Codex 작업은 단일 목적과 제한된 파일 범위를 가진다. |
| NFR-D-002 | 구현 전에 인수 조건과 테스트 전략이 존재해야 한다. |
| NFR-D-003 | 1인 개발자가 디버깅 가능한 로그와 시각화 도구를 제공한다. |
